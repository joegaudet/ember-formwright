Forms for Ember 6.12 LTS and 7

Write the form. The wiring writes itself.

One <Form>, one <f.Field>. Labels, ids, errors, aria-invalid, dirty state, reset and nested saves are handled. Bring any validator (zod, valibot, any Standard Schema) and any data layer (WarpDrive, ember-data, plain objects). Then test it with harnesses that read the way your users do.

$ npm i @ember-formwright/ember

Add @ember-formwright/test-support for harnesses, and an adapter if you use one.

Why

A field is ten things. You should write one.

An accessible field needs a label tied to its input, a hint and an error region the input is described by, aria-invalid at the right moment, a value bound one way and written back on change, and dirty state that knows what "unchanged" was. Formwright does all of it from a model path.

By hand, for every field
<label for="email-input">Email</label>
<input
  id="email-input"
  type="email"
  value={{this.user.email}}
  aria-invalid={{if this.errors.email "true"}}
  aria-describedby="email-hint email-errors"
  {{on "input" this.updateEmail}}
/>
<p id="email-hint">We never share it</p>
<ul id="email-errors" aria-live="polite">
  {{#each this.errors.email as |e|}}<li>{{e}}</li>{{/each}}
</ul>
With Formwright
<Form @model={{this.user}} @validator={{userSchema}} as |f|>
  <f.Field
    @for="email"
    @control="email"
    @label="Email"
    @hint="We never share it"
  />
  <f.Submit />
</Form>

Any validator

Pass a zod, valibot or ArkType schema, anything that speaks Standard Schema, or a plain function. Issue paths land on the right field.

Any data layer

Plain objects and @tracked classes work out of the box. An adapter teaches it WarpDrive and ember-data: save, rollback, server errors.

Accessible by default

Labels, legends for groups, aria-describedby, live error regions, and focus on the first invalid field. Every test runs axe.

Inline editing

Click a value to edit it in place, or in a native popover anchored with CSS. Confirm with ✔, cancel with Esc. No positioning library.

Usage

Strict mode, named args, nothing to register

Import Form into a .gts template. Fields, nested forms and buttons come from the form itself, already bound to it. With Glint, the whole form is typed by its model: each @for must be a real path (a typo or a wrong nested path fails the typecheck), and field values, @format, errors and hooks take the type at that path. 

import { Form } from '@ember-formwright/ember'
import '@ember-formwright/ember/theme.css' // optional

<template>
  <Form @model={{@order}} @name="checkout" @onSubmit={{@save}} as |f|>
    <f.Field @for="email" @control="email" @label="Email" @required={{true}} />
    <f.Field @for="size" @control="select" @label="Size" @options={{SIZES}} />
    <f.Field @for="gift" @control="checkbox" @label="This is a gift" />

    <f.Form @model={{@order.address}} @name="address" @legend="Ship to" as |a|>
      <a.Field @for="city" @label="City" />
    </f.Form>

    <f.Errors />
    <f.Submit>Place order</f.Submit>
    {{#if f.state.isDirty}}Unsaved changes{{/if}}
  </Form>
</template>

Built-in controls: input, email, password, search, tel, url, number, range, color, date, datetime, time, textarea, select, radio, checkbox, checkbox-group and currency (formatted with Intl). Pass any component to @control, or register one by name.

Validation

Bring the schema you already have

Validation runs on submit. After a failed submit it re-runs on every change, so errors clear as they are fixed. Nested forms validate with their root. 

import { z } from 'zod'

export const userSchema = z.object({
  email: z.string().email('That email looks off'),
  address: z.object({
    city: z.string().min(1, 'City is required'),
  }),
})
// "address.city" errors show on <f.Field @for="address.city">
// Or a function: return messages by path.
// The empty path is for form-level errors.
const validator = (user: User) => ({
  ...(user.password !== user.confirm && {
    confirm: ['Passwords must match'],
  }),
  ...(user.banned && { '': ['This account is locked'] }),
})

Testing

Harnesses: tests that read like your users

Describe a form once as a harness class. Decorators declare its fields, each with the harness for its control, and its nested forms. Every harness is created once and looks up the DOM live, so it survives re-renders. Custom controls get their own harness by subclassing FieldHarness. 

import {
  FormHarness, InputHarness, SelectHarness,
  CheckboxGroupHarness, CheckboxHarness, field, form,
} from '@ember-formwright/test-support'

export class AddressForm extends FormHarness {
  @field(InputHarness) declare city: InputHarness
}

export class SignupForm extends FormHarness {
  static formName = 'signup'

  @field(InputHarness) declare email: InputHarness
  @field(SelectHarness) declare plan: SelectHarness
  @field(CheckboxGroupHarness) declare notify: CheckboxGroupHarness
  @field(CheckboxHarness) declare terms: CheckboxHarness
  @form(AddressForm) declare address: AddressForm
}
test('signing up', async function (assert) {
  await render(<template><Signup /></template>)
  const signup = new SignupForm()

  await signup.email.fillIn('ada@example.com')
  await signup.plan.select('team')
  await signup.notify.select(['email', 'sms'])
  await signup.address.city.fillIn('Lisbon')
  await signup.submit()

  assert.deepEqual(signup.terms.errors, [
    'Please accept the terms',
  ])
  assert.true(signup.terms.isInvalid)
})
Selector On
data-test-fw-form="signup" The <form>, or a nested form's <fieldset>
data-test-fw-field="address.city" A field, by model path. items[0].name normalizes to items.0.name.
data-test-fw-path="signup.address.city" The same field, from the root form
data-test-fw-type="select" The control a field uses; the harness picks a driver from it
-label -hint -error -option -submit -reset -commit -cancel -display The parts of a field and form

Adapters

Small packages for the rest of your stack

The core edits any object. Each adapter is a few dozen lines, so it is easy to read, and easy to write your own.

Package What it adds
@ember-formwright/warp-drive WarpDrive and ember-data records: save() on submit, rollbackAttributes() on reset, server errors on their fields, new nested records saved with their parent.
@ember-formwright/real-enums real-enums classes as @options, filtered with enumOptions, stored as members or raw strings, shown with their labels.
@ember-formwright/maskito A masked control powered by Maskito: phones, cards, dates.
@ember-formwright/test-support The form harnesses above, with drivers you can extend for custom controls. 
// app/app.ts: every form edits WarpDrive records
import { setDefaultAdapter } from '@ember-formwright/ember'
import { warpDriveAdapter } from '@ember-formwright/warp-drive'

setDefaultAdapter(warpDriveAdapter)

  @options={{enumOptions OrderState except=(array OrderState.Cancelled)}} />
